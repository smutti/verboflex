<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| OAuth2 form/IP -> login service | Untrusted identifiers, passwords, and network metadata request authority. |
| Bearer JWT -> database principal | Caller-controlled token claims are reconciled with durable active/version/role state. |
| Redis -> authentication availability | External limiter state decides whether password verification may run. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-01 | Spoofing | JWT verification | high | mitigate | Explicit algorithm/signature/expiry/claim checks plus database token_version and active-user lookup. |
| T-04-02 | Information Disclosure | login errors | high | mitigate | Identical 401 body/header and dummy hash path for wrong/unknown/inactive cases. |
| T-04-03 | Denial of Service | password verification | high | mitigate | Redis limiter before Argon2; fail closed for login when Redis is unavailable. |
| T-04-04 | Elevation of Privilege | roles and token purpose | high | mitigate | Roles loaded from PostgreSQL, reusable server dependency, password-change purpose denied from normal resources. |
| T-04-05 | Tampering | refresh session creation | high | mitigate | Store only SHA-256 token hash and commit session/cookie atomically. |
</threat_model>
