# Phase 4 — UI Design Contract

> Visual and interaction contract for canonical localization import, translation search and detail, and maximum-character constraints. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## Scope and Provenance

Phase 4 extends the existing authenticated VerboFlex application in four bounded places:

- The existing published-mapping import surface reports canonical parsing outcomes while preserving the last successful translation dataset after a failed refresh.
- The existing candidate preview confirmation records exactly one base language selected from detected languages when it cannot be determined unambiguously.
- A new all-role Translations destination provides cursor-backed, virtualized search over canonical translation groups.
- A URL-backed translation detail route exposes structured values, review/source context, and role-aware maximum-character constraint management.

This contract preserves `04-CONTEXT.md` decisions D-01 through D-23, Phase 4 requirements FMT-01 through FMT-04, FMT-06 through FMT-08, SRCH-01 through SRCH-08, and CONS-01 through CONS-05. It also inherits the approved Phase 2 and Phase 3 shell, responsive patterns, generated-client authority, import state, and visual tokens.

Phase 4 must not expose translation-text editing, comment creation, review-state mutation, key creation/deletion, provider writes, commits, pull requests, bulk constraint operations, or an inferred key-rename action. Review state, comment absence, and pending-change absence are read-only context in this phase.

### Product language and untrusted content

All application chrome and user-facing copy remains English, matching the existing application. Repository keys, source and translated text, typed selectors, paths, branches, parser locations, and provider metadata are untrusted data: render them only as text nodes. Never render imported markup through `dangerouslySetInnerHTML`, turn detected URLs into links automatically, interpolate raw parser/provider exceptions, or place raw source text in a URL.

Translation content blocks use the server-projected BCP 47 language tag in `lang` and `dir="auto"`; the application chrome remains left-to-right. This supports mixed-script content without claiming full RTL application support.

## Information Architecture

| Screen / Surface | Route | Purpose | Primary elements |
|------------------|-------|---------|------------------|
| Translation Search | `/translations` | Search and filter canonical translation groups across authorized products and languages. | Search input, five filters, loaded count, virtualized result list, load-more fallback. |
| Translation Detail | `/translations/:translationGroupId` | Inspect one server-owned key-and-language group without flattening structured selectors. | Back link, identity/status summary, source and translated values, constraint section, repository provenance, read-only review context. |
| Mapping Import Result | Existing `/admin/products/:productId/mappings` | Extend one published mapping row with bounded canonical parser failure and last-dataset state. | Existing import status/action plus bounded parser issues. |
| Base-language Selection | Existing `/admin/products/:productId/preview` | Bind one detected language as the mapping base-language authority before preview confirmation/publication. | Detected-language Select, inheritance explanation, existing confirm/publish controls. |
| Constraint Form | Dialog from Translation Detail | Create or edit one key-and-language maximum-character rule. | Visible label, numeric input, inheritance explanation, cancel/save actions. |
| Constraint Removal | Alert Dialog from Translation Detail | Remove one override or base-language default with explicit consequence. | Named title/body, cancel, destructive confirm. |

### Navigation and authority

- Add `Translations` with the Lucide `Languages` icon directly after `Workspace` in the ordinary primary navigation. It is visible to every authenticated role in both the desktop Sidebar and mobile Sheet.
- Keep `Products`, `Users`, and `Bitbucket` inside the existing administrator-only group. Do not place search under Administration.
- Mount one feature-level `TranslationsWorkspace` at `/translations/*` so search/filter/virtual-scroll state stays in React memory while users move between the search and detail child routes. Do not add a global store.
- Search and detail are readable by every authenticated role for server-authorized products. The server-loaded principal and generated responses remain authoritative; visible roles never broaden product access.
- Only `admin` and `product_manager_reviewer` may see constraint mutation controls. `translator` and `viewer` receive the same readable effective-limit and violation status but no disabled or hidden-by-tooltip mutation affordance.
- Base-language selection remains administrator configuration. Product manager/reviewer authority over constraints does not grant candidate-revision or publication authority.
- Use an opaque server-owned `translationGroupId` in the route. Never construct the route from a product name, repository key, language, path, or structured selector.

### Base-language authority

- Add `Base language` to the current successful preview candidate, populated only from the candidate's exact detected-language list. It is a Select, not free text.
- If exactly one language is detected, select it deterministically and show it visibly before confirmation. If more than one is detected, start unselected and block `Confirm preview` until the administrator chooses one. Never guess from ordering, locale spelling, or a conventional `en` value.
- The confirmed preview and published mapping retain the selected language. Changing it invalidates preview confirmation and follows the existing candidate edit, revalidation, and atomic publication flow.
- A legacy published mapping with missing or ambiguous base-language authority fails the canonical import atomically. Its mapping row shows `Base language required`; an administrator gets `Configure base language`, linking to that product's Preview route, while non-administrator search users see no partial candidate dataset.

## Visual and Layout Contract

### Focal hierarchy

**Translation Search**

1. `Translations` page title and one-line purpose.
2. Search field, then product/language and state filters.
3. Applied-result summary and any recoverable load state.
4. Dense translation-group results with the explicit detail link.

**Translation Detail**

1. `Translation details`, `Back to translations`, and raw repository key.
2. Translated/source content and any over-limit state.
3. Effective maximum-character rule and its inheritance source.
4. Repository provenance and read-only review context.

### Search layout

- Preserve the full-width authenticated shell, `24px` gutters below `768px`, `32px` gutters from `768px`, and `32px` between page sections.
- Put the visible `Search keys and translations` label and full-width Input on its own row. Its helper text is `Searches original keys, source text, and translated text.`
- Put filters in this exact order: `Product`, `Language`, `Approval state`, `Length status`, `Deleted status`. Use one column below `768px`, two columns from `768px`, and five equal minmax columns from `1280px`.
- Place `Clear filters` as an outline Button after the filter grid, not inside an input or Select. It clears the query and returns all five filters to their documented default values.
- The result collection is a flat border-separated semantic list, not a card grid or table. Window virtualization prevents a nested scroll container and keeps the browser/page scrollbar authoritative.
- Each desktop result row uses a six-part grid: key, language, source excerpt, translated excerpt, state/length status, and `Open details`. Below `768px`, preserve that DOM order in one stacked article.
- Result rows have `16px` internal spacing and one separator. Do not nest cards, add row shadows, or make the entire row a click target.
- A result excerpt is at most two visual lines. Detail links provide the full content; do not expand rows inline. Raw keys wrap with `overflow-wrap:anywhere` and remain monospace.
- The result link visibly says `Open details`; its accessible name adds the repository key and language without repeating the full translation.

### Result anatomy and aggregation

- One result represents exactly one server-owned original-key-and-language group. Show the byte-preserved key unchanged; never append dots, brackets, quantities, indices, or JSON segments to synthesize a display key.
- Show language as server-projected locale plus friendly label when available, for example `Italian (it-IT)`. The locale remains visible when no friendly label exists.
- Scalar groups show no selector decoration. Structured groups show `{count} values` and compact neutral selector-type labels such as `Plural`, `Array`, `Qt variant`, or `JSON path`; do not concatenate selectors into the key.
- If all canonical values share one review state, show `Draft`, `Approved`, or `Rejected`. Mixed values show neutral `Mixed states`; detail lists each value's state.
- Approval-state and violation filters match a group when at least one current canonical value matches. The result row must not imply that every value matched: show `Mixed states` or `{violating} of {total} over limit` where applicable.
- Deleted results show a text Badge `Deleted in source` and last-known provenance. They appear only when `Deleted status` is `Deleted only` or `Active and deleted`.
- A renamed repository key therefore appears as one `Deleted in source` result under the old byte-preserved key and one independent new result. No rename suggestion, merge control, or visual connector is allowed.

### Search controls and default values

| Control | Options / behavior | Default |
|---------|--------------------|---------|
| Search keys and translations | Case-insensitive key/source/translated-text query; 300ms debounce; Enter runs immediately; explicit clear control | Empty |
| Product | `All products`, then server-authorized products in server order | Last valid remembered product, else `All products` |
| Language | `All languages`, then languages available for the selected product scope in server order | Last valid remembered language, else `All languages` |
| Approval state | `All states`, `Draft`, `Approved`, `Rejected` | `All states` |
| Length status | `All length statuses`, `Over limit`, `Within limit`, `No max length` | `All length statuses` |
| Deleted status | `Active only`, `Deleted only`, `Active and deleted` | `Active only` |

- Persist only selected product ID and language identifier in a principal-scoped local preference, for example `verboflex.translation-search.{principalId}`. Revalidate both against current server-authorized options before using them.
- Never persist the free-text query, translation content, repository key, source text, or filter result in localStorage/sessionStorage. The feature-level route state may retain them in React memory for the current navigation session.
- When product scope changes, revalidate Language. If unavailable, select `All languages` before requesting results.

### Virtualized infinite loading

- Request exactly 50 translation groups per server cursor page. Render with `useWindowVirtualizer`, dynamic `measureElement`, an initial largest-row estimate of `288px` for the stacked mobile anatomy, `overscan: 8`, and `useFlushSync: false`.
- Start the next request when the final rendered index enters the eight-row overscan window. Also render a keyboard-operable `Load more translations` Button after the virtualized region whenever `next_cursor` exists; automatic intersection/loading cannot be the only path.
- Show `50 translation groups loaded`-style copy using only the number currently loaded. If no total is supplied, never invent `of {total}` or a percentage.
- Preserve server order. The UI does not rerank exact/prefix/partial matches, client-sort, deduplicate by visible text, or use offsets.
- Every search/filter change increments a request generation, clears the loaded cursor chain, scrolls to the result heading, and prevents any prior response from entering the new collection.
- Repeated cursors, an empty non-terminal page, mixed filter authority, or a page over the response bound stops further loading, retains already valid rows, and uses the load-more error contract. Never loop or expose a partial new page as complete.
- Render only visible rows plus overscan. Use `role="list"`; each rendered row uses `role="listitem"`, its one-based loaded position in `aria-posinset`, and `aria-setsize="-1"` until the terminal cursor is known, then the exact loaded count.

### Detail layout

- Use a full page rather than a modal or Sheet. Keep one `h1` (`Translation details`) and a visible `Back to translations` link before it.
- Below `1280px`, stack all sections. At `1280px` and above, use `minmax(0,2fr) minmax(18rem,1fr)`: content in the main column; constraint, source context, and review context in the aside.
- Use flat bordered Secondary sections with `24px` padding and `8px` radius. Do not place cards inside cards.
- `Translation content` lists each canonical value separately. Scalar values use `Default value`. Structured values use a definition list that exposes selector type and each typed selector field independently: for example `Quantity: one` or `Array position: 1`. Never display a synthesized key.
- Show source and translated text as read-only `white-space: pre-wrap` blocks with `overflow-wrap:anywhere`, `lang`, and `dir="auto"`. Imported markup is shown as safe structure metadata or literal text according to the generated representation, never executed as DOM.
- Each value shows its own review-state text and actual grapheme count. If a group is mixed, its section heading carries `Mixed states` and the individual values remain authoritative.
- `Source context` shows product, repository, configured branch, last-known file path, format, repository side, and abbreviated import commit with explicit `Copy full commit`. Paths, branch, key, selectors, and commits use monospace; no provider deep link is added.
- `Review context` shows `Pending change: None` and `Comments: No comments yet` in Phase 4, plus the current read-only review state. Do not add editor, comment composer, state controls, or disabled future actions.
- A deleted group keeps all last-known content, constraints, state, and provenance visible beneath a `Deleted in source` Badge. It is never treated as a 404 merely because it is excluded from normal search.

### Constraint presentation

- The group-level `Maximum length` section shows the effective maximum, its source, and one row per canonical value with `Actual`, `Maximum`, and a text status.
- Use these exact status labels: `No max length`, `Within limit`, and `Over limit by {count}`. For multiple values, summarize `{violating} of {total} over limit` when any violate.
- Count and display user-perceived Unicode characters (extended grapheme clusters). A combined emoji or composed character counts once. Exclude non-visible format markup from the display count. Never label this count bytes, code points, UTF-8, or UTF-16 units.
- A base-language rule is labeled `Base-language default`. A target using it is labeled `Inherited from {base language}`. A target-specific value is labeled `Language override`.
- Base-language detail with no default uses `Set max length`. Existing base default uses `Edit max length` and `Remove base limit`.
- Target detail with no effective limit uses `Set max length`. An inherited target uses `Add language override`; an overridden target uses `Edit max length` and `Remove language override`.
- A group is visually warning/amber when one or more values violate. Keep translated text readable and present; do not redact, truncate further, or use destructive red. Supporting text says `This translation can remain Draft, but it cannot be approved or submitted while over the limit.`
- Search and detail consume server-calculated counts and violation states. The browser may preview a typed constraint value but never becomes the authoritative grapheme counter or approval gate.

## Interaction Contracts

### Search execution and state restoration

- Resolve the authorized product and language option sets before the first result query. Validate the remembered IDs against those sets; silently discard stale or unauthorized values and use `All products`/`All languages`.
- Search is case-insensitive over original key, source text, and translated text. The backend ranks exact matches before prefixes and prefixes before partial matches; the browser preserves the returned order.
- Debounce typing by 300ms. Enter cancels the debounce and runs the current query once. Clearing the field runs the empty query once. Duplicate parameter sets must not issue duplicate requests.
- Filter changes apply immediately. Any changed dimension invalidates every loaded cursor, scrolls the result heading into view without animation under reduced motion, and keeps keyboard focus on the changed control.
- Before opening detail, retain the result-query snapshot, virtual scroll offset, and invoking group ID in the feature-level React state. Browser Back restores the list and returns focus to that group's `Open details` link after it is rendered. A direct detail URL uses `Back to translations` to open the default/restored search state.
- Never expose a sort control: relevance plus deterministic server tie-breakers are canonical for non-empty queries, and the server's deterministic default order is canonical for empty queries.

### Search collection states

- Initial loading uses five geometry-matched result Skeleton rows and `Loading translations` in a polite status region. Filter controls remain visible; controls whose options are not yet authorized stay disabled.
- A successful collection announces `{count} translation groups loaded` once per completed query generation. Additional cursor pages announce `Loaded {count} more translation groups`; scrolling itself is silent.
- When the authorized scope contains no canonical translations, show `No translations available` and `Complete an import for an active product, or choose another authorized product.`
- When data exists but the current query/filters return zero, show `No translations match these filters` and `Change your search or clear the filters to see more translations.` with `Clear filters`.
- Initial failure replaces only the result region with `Translations could not be loaded`, `Your filters are still available. Retry the search without leaving this page.`, and `Retry search`.
- Load-more failure retains all valid rows and shows `More translations could not be loaded` with `Retry loading more`. It does not reset scroll, blank results, or restart the first cursor.
- A superseded response is discarded silently. It must not announce an error, change an empty state, or restore an old cursor.

### Detail states and navigation

- Detail loading renders geometry-matched Skeleton sections and `Loading translation details`. It does not replace the application shell or search state.
- A missing or inaccessible opaque ID renders `Translation not available`, `This translation may have been removed or is outside your authorized products.`, and `Back to translations`; do not distinguish authorization from absence.
- Other detail failure renders `Translation details unavailable`, `We could not load this translation. Retry without losing your search.`, and `Retry details`.
- A canonical group always keeps raw key and structured selectors separate. Scalar, plural, array, Qt variant, and nested JSON values use the same section anatomy rather than format-specific bespoke screens.
- Source text absence is explicit: `No source text available`. An empty translated string is explicit: `Empty translation`. Do not collapse either into a blank region.
- Show the complete current group returned by the detail API. If the backend flags it incomplete, stale, or mixed-authority, render a blocking Alert and omit constraint mutations until a fresh complete projection succeeds.
- Copying a full commit is user-initiated, announces `Full commit copied`, and never places the hash in a toast automatically.

### Constraint create and edit

- `Set max length`, `Add language override`, or `Edit max length` opens one Dialog titled `Set maximum length` or `Edit maximum length`.
- Body copy: `Maximum length counts visible characters. A combined emoji or composed character counts as one.`
- The visible numeric field label is `Maximum characters`. Use the generated API's integer bounds for HTML attributes and validation; client validation mirrors but never widens server authority.
- For a base language, show `Languages without their own override inherit this value and will be recalculated.` For a target language, show either `This value overrides the {base language} default.` or `No base-language default is currently available.`
- Form actions are `Cancel` and `Save max length`. Submission disables both actions, sets `aria-busy="true"` on Save, prevents outside-click/Escape closure, and uses one state-plus-ref duplicate-submit guard.
- On backend success, update only from the returned/fresh generated projection, close the Dialog, announce `Maximum length saved`, and invalidate the affected search-group cache so the restored row shows current status.
- Validation failure stays below `Maximum characters`, sets `aria-invalid`, preserves the entered value, and focuses the field. General failure focuses an Alert containing `Maximum length was not saved` and `Review the value and try again.`
- A version/currentness conflict keeps the Dialog open, focuses `Maximum length changed`, and says `This constraint changed in another session. Reload the current value before saving again.` The action is `Reload current value`; replacing the entered value requires explicit confirmation.
- No search-row inline edit or bulk constraint action is permitted.

### Constraint removal

- Removal is non-optimistic and always uses Alert Dialog. While pending, disable both actions, set `aria-busy` on the confirm action, and prevent outside-click/Escape closure.
- Base default title: `Remove the base-language limit?`
- Base default body: `Languages without their own override will have no maximum length. Existing language overrides will remain.`
- Base confirm label: `Remove base limit`.
- Override title: `Remove the {language} override?`
- Override body when a base default exists: `This language will inherit the current {base language} maximum of {count} characters.`
- Override body without a base default: `This language will have no maximum length.`
- Override confirm label: `Remove language override`.
- On success, use the fresh projection, announce `Maximum length removed`, and refresh the corresponding search row. Failure keeps the dialog open with `Maximum length was not removed. Try again.`

### Import parser outcome and last-success preservation

- Extend the existing Phase 3 mapping row; do not add a separate parser-errors route, modal, timeline, or global banner.
- A failed canonical parse keeps the last successful baseline and active translation dataset fully visible. Label it `May be stale`; with no prior successful canonical dataset, use `Import failed` and `No translation dataset was created.`
- The owning row Alert title is `Localization files could not be imported`. Body: `One or more configured files are malformed, ambiguous, or contain unsupported structure. The last successful translation dataset remains active.` Replace the final sentence with `No translation dataset was created.` when appropriate.
- Show at most five stable server-projected issues in repository-side then provider file order. Each issue shows a closed category (`Malformed file`, `Ambiguous structure`, `Unsupported structure`, `Duplicate key`, or `Base language required`), repository side, path, and safe line/column when available. It never shows source excerpts, raw exceptions, XML/JSON fragments, or provider bodies.
- If more issues exist, show `And {count} more errors.` No expand/bypass action is allowed. The existing mapping-level `Retry import` remains the only retry.
- A separate mapping reports Keys then Translations issues inside one atomic failure. Never imply one side became active.
- `Base language required` adds the administrator-only `Configure base language` link described above. Every other parser issue directs the administrator to inspect the configured source and retry; the UI never offers to ignore unsupported content.

### Refresh-visible identity behavior

- Moving the same byte-preserved key between files keeps the same result/detail identity and updates only the displayed last-known file path after a successful import. It must not flash as deleted plus added or lose Back-navigation focus identity.
- A renamed key remains the two-result delete-plus-add presentation defined above. The browser never compares equal text to suggest a move or rename.
- An externally changed translated value appears only after the fresh activated dataset projection, keeps its constraints/comments seam, and shows `Draft` as returned by the server. A source-text change similarly leaves target text visible while every affected target-language value shows `Draft`.
- A future exact VerboFlex-submitted value may remain `Approved` only when the generated server projection proves submission correlation. Equal text, a matching commit prefix, cached UI state, or client comparison never produces `Approved` or `Synchronized` presentation.
- Failed, stale, or partial imports never alter visible canonical text, states, constraints, comments, pending status, or search membership from the last successful dataset.

### Open-axis considerations

- Network loss follows the owning search/detail/constraint/import error path. There is no offline search cache, offline mutation queue, or optimistic constraint state.
- Search is request/response and cursor based. No WebSocket, collaborative presence, live-edit indicator, or auto-refresh that moves list position is introduced.
- Respect `prefers-reduced-motion`; filter reset, focus restoration, virtual scrolling, Skeletons, and Dialog behavior remain complete without animation.
- Full UI localization, RTL chrome mirroring, print layouts, voice, gesture-only controls, and translation editing are outside Phase 4. Per-content `lang` and `dir="auto"` remain required.

## Accessibility Contract

- Maintain one `h1` per route and hierarchical `h2` section headings. Dialog title/description and Alert Dialog title/body are programmatically associated.
- Every search/filter/input control has a persistent visible label. Placeholder text never substitutes for a label.
- The virtualized result region has an accessible name, list/listitem semantics, loaded-position metadata, and a keyboard-operable load-more fallback. Virtualization must not trap Tab or reset focus when rows are measured.
- Announce completed result generations and appended-page counts only. Typing, every scroll event, and discarded stale responses remain silent.
- When Back restores search, focus returns to the invoking `Open details` link without forcing scroll if it is already visible. Direct detail navigation focuses `Translation details` after load.
- Search and detail state, deleted status, review state, inheritance, and violation status always include readable text. Color and icon shape remain supplementary.
- On user-triggered load/mutation error, focus the owning Alert. Background or superseded failures do not steal focus.
- Constraint Dialogs trap focus; successful/cancel closure restores focus to the invoking action. Pending save/removal cannot be dismissed into uncertain state.
- Translation text uses its language tag and automatic direction without altering the direction of controls. Combined characters must not be split for visual count highlighting.
- Local copy controls have visible focus, Tooltip, and explicit accessible names. Full hashes are announced only after user-invoked copy.
- Touch targets are at least `44px × 44px` on coarse pointer/mobile. Search, filter, result, back, retry, and constraint actions do not depend on hover.
- The page must reflow without horizontal page scrolling at `320px` and 200% zoom. Long action labels wrap rather than truncate.
