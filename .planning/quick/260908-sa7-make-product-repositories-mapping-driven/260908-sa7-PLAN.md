# Quick task 260908-sa7: Mapping-driven product repositories

## Goal

Remove the misleading product/repository selection model from the standalone product page and make repository usage, empty states, errors, and actions clear and accessible.

## Decisions

- A saved mapping remains the only persistent product-to-repository association.
- The standalone product Repositories page derives its content from the editable revision mappings and never presents unrelated global repositories as already associated.
- The embedded wizard keeps the global repository catalogue because it prepares the next mapping step, but its copy must state that the association is saved only with a mapping.
- No database or API contract change is required.

## Tasks

1. Add failing tests for mapping-scoped repository visibility, empty state, route wiring, and accessible catalogue guidance.
2. Extract bounded mapping-to-repository resolution shared by the product wizard and repository page.
3. Add a focused product repository view with clear hierarchy, semantic status, accessible loading/error states, and direct mapping actions.
4. Clarify the embedded global catalogue and registration form without changing persistence semantics.
5. Run targeted and full frontend checks, build, and refresh the local Docker frontend.

## Verification

- Product repository and product configuration suites pass.
- Full frontend tests, lint, formatting, and production build pass.
- The rebuilt local frontend responds successfully.
