# Phase 1 - UI Design Contract

> Visual and interaction contract for the Platform Foundation frontend. Generated by gsd-ui-phase, verified by the UI checker.

---

## Scope

Phase 1 UI delivers the first runnable VerboFlex shell only:

- Unauthenticated login screen for the internal OAuth2 password flow.
- Session-aware application chrome after login.
- Neutral landing dashboard that can later adapt by role, usage, or product context.
- Empty placeholders for future modules without implementing product, repository, localization, review, comment, constraint, Bitbucket, or pull request workflows.
- API connectivity and service-status feedback needed to prove the generated OpenAPI client and backend are wired.

Out of scope: product/repository configuration, translation search, review workspace, comments, constraints, parser previews, Bitbucket setup, PR submission, and Figma context.

- Use lucide icons inside buttons where an icon clarifies the action.

## Visual and Interaction Contract

### Focal Point

The primary visual anchor after login is the top-left product identity plus the dashboard title `Workspace overview`. The secondary anchor is the service-status strip showing API, database, Redis, and worker status. Future module placeholders must sit below those anchors and must not compete visually with the shell.

### Visual Hierarchy

1. Product identity and active navigation.
2. Page title and session/role summary.
3. Service-status strip.
4. Future-module placeholders.
5. Low-emphasis support text and timestamps.

### Layout

- Desktop: fixed left sidebar plus main content column.
- Tablet/mobile: top bar with a menu button that opens a shadcn sheet-based navigation surface once the sheet component is installed.
- Main content width should use the available viewport; do not center a marketing-style hero.
- Login screen may use a single form panel, but no nested cards.
- Dashboard placeholders use unframed sections or individual panels; do not place cards inside cards.

### Interaction States

- Buttons must expose default, hover, focus-visible, disabled, and loading states.
- Icon-only controls require tooltip text and accessible labels.
- Auth errors appear inline above the login button.
- API connectivity errors use a visible alert with a retry action.
- The app must never persist tokens to `localStorage` or `sessionStorage`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, tight inline separation |
| sm | 8px | Input label gaps, compact toolbar gaps |
| md | 16px | Default element spacing, form field rhythm |
| lg | 24px | Page section padding, panel interior spacing |
| xl | 32px | Main content gutters, dashboard group gaps |
| 2xl | 48px | Major vertical breaks between shell regions |
| 3xl | 64px | Maximum page-level spacing on wide desktop |

Exceptions: none.

## Typography

Use exactly these four sizes and two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.3 |
| Body | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.25 |
| Display | 28px | 600 | 1.15 |

Rules:

- Do not use viewport-scaled font sizes.
- Letter spacing is `0`.
- Use Body for dashboard copy, table-like status rows, and form help text.
- Use Heading for screen titles and major panel titles.
- Use Display only for the login product mark or the authenticated dashboard title, not inside compact controls.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` | Page background and broad shell surfaces |
| Secondary (30%) | `#FFFFFF` | Panels, form surface, status rows, nav surface |
| Accent (10%) | `#0F766E` | Primary login CTA, active nav indicator, focus ring, selected status marker, inline links |
| Destructive | `#DC2626` | Authentication failure text, destructive confirmation in later phases |

Accent reserved for: primary login CTA, active navigation indicator, focus-visible ring, selected status marker, inline links. Accent must not be used for every button, every icon, or every hover state.

Supporting neutral values:

- Primary text: `#111827`
- Secondary text: `#4B5563`
- Muted text: `#6B7280`
- Border: `#E5E7EB`
- Success: `#15803D`
- Warning: `#B45309`

## Accessibility Contract

- Every input has a visible label and programmatic label.
- Error text is associated with the relevant form or alert region.
- Focus-visible state uses the accent color and must be visible against both dominant and secondary surfaces.
- Role badges are text-first; color alone must not encode role meaning.
- Service statuses must use text labels such as `API online`, `Redis unavailable`, and `Worker pending`.
- Keyboard users can reach login fields, primary CTA, navigation, user menu, and retry action in visible order.

## Implementation Guardrails

- Build the actual app shell, not a marketing landing page.
- Keep the interface quiet and task-focused; no hero section, decorative illustration, gradient/orb background, or feature-tour content.
- Do not use nested cards.
- Keep card/panel radius at 8px or less.
- Use full-width application bands and constrained inner content instead of floating page sections.
- Keep all text within its parent across mobile and desktop widths.
- Generated OpenAPI client surfaces may be referenced in UI state, but do not hand-write API types.
- Future modules may be visible only as neutral placeholders; they must not expose fake Bitbucket, product, search, review, comment, constraint, or PR functionality.
